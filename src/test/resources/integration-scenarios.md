# Проверки на Paper 1.21.11 (Java 21)

Эти проверки требуют настоящего сервера и двух клиентов. Модульные тесты не заменяют проверку редстоуна и физики жемчуга.

Собрать: `./gradlew clean build`. Поместить JAR из `build/libs` в `plugins`, запустить сервер. Включить `debug: true` в `plugins/OlisPearlFix/config.yml` и перезапустить сервер. Обновление через `/reload` не поддерживается.

Построить обычную рабочую пузырьковую стазис-камеру с люком и деревянной нажимной плитой. До установки плагина проверить: снятие поплавка с плиты закрывает люк и приводит к столкновению жемчуга. Убедиться, что рядом нет посторонних сущностей на плите. Камеры должны иметь отдельные жемчуги и плиты. Камень и полированный чернокамень не реагируют на поплавок по правилам Minecraft; они не поддерживаются. Взвешенные плиты сохраняют минимум сигнала одного поплавка (золотая и железная — 1).

Игрок A бросает свой настоящий жемчуг, затем забрасывает удочку на плиту. Дождаться сообщения о привязке. `/stasis list` показывает UUID камеры и HELD. Для каждой проверки ниже использовать новую камеру после расходования жемчуга.

| Сценарий | Шаги | Ожидаемый результат |
| --- | --- | --- |
| Удалённая активация | A отходит более чем на 64 блока, нажимает ПКМ той же удочкой | Только её плита отпускается; ванильное столкновение жемчуга телепортирует A |
| Выход и вход | A выходит на несколько минут; B остаётся у камеры; затем A входит и нажимает ПКМ | Плита непрерывно нажата, люк не переключается до ПКМ; один жемчуг, одна привязка |
| Измерения | A проходит в Nether/End, затем использует удочку | Привязка сохранена; телепортацию между мирами выполняет настоящий жемчуг |
| Выгрузка чанка | На тестовом сервере с `misc.legacy-ender-pearl-behavior: true` и без force-load оба игрока удаляются за view-distance; затем A нажимает ПКМ | Чанк загружается по запросу; после обработки временные tickets освобождены |
| Перезапуск | Полная остановка через `stop`, запуск, вход A, ПКМ | UUID камеры и удочки совпадают; плита не отпускается при запуске |
| Несколько камер | A привязывает две разные удочки к разным камерам, использует одну | Срабатывает только выбранная камера |
| Одновременная работа | A и B активируют собственные камеры одновременно, в том числе в одном чанке | Обе активации работают; временный ticket общего чанка не удаляется раньше времени |
| Слоты и сундук | Переложить удочку между слотами, в сундук, затем забрать | ID и камера сохранены; перемещение само по себе не активирует камеру |
| Передача | A передаёт удочку B; B использует её | При живом A онлайн телепортируется A, владелец жемчуга; когда A офлайн, привязка остаётся HELD |
| Смерть | A умирает с активной камерой | Ванильное правило `ender_pearls_vanish_on_death` соблюдается; удаление жемчуга удаляет привязку, без API-телепортации |
| Разрушение плиты | B пытается сломать плиту/опору, применяет поршень, взрыв или воду | Активная плита защищена; владелец может безопасно отменить её через `/stasis cancel UUID` и затем разобрать |
| Уничтожение удочки | Выбросить удочку в лаву или дождаться despawn | Жемчуг удаляется до снятия привязки; если A офлайн, DISARMING завершается после его входа |
| Потеря в сундуке | Потерять доступ к удочке, выполнить `/stasis cancel UUID` | Только владелец или администратор отменяет камеру; жемчуг удаляется без телепортации |
| Быстрые нажатия | Несколько ПКМ во время асинхронной загрузки | Один запрос на привязку; нет новых поплавков и повторной активации |
| Выход во время загрузки | A нажимает ПКМ издалека и сразу отключается | Незавершённый запрос отменяется, tickets удаляются, камера остаётся HELD |
| Исчезновение жемчуга | На тестовом сервере удалить именно связанный жемчуг | Привязка очищается, жемчуг не создаётся заново |
| Недоступный мир | Остановить сервер, временно убрать мир камеры, запустить | Нет бесконечных загрузок; запись остаётся до возвращения того же мира с тем же UUID |
| Копия удочки | Администратор копирует предмет вместе с PDC, использует обе копии | Копии адресуют одну привязку; один жемчуг; при новом забросе ID обновляется |
| Обычная рыбалка | Забросить удочку в обычный водоём без плиты и жемчуга | Ванильная рыбалка, добыча и расход прочности работают |

При обычном поведении Minecraft 1.21.11 жемчуг сам добавляет tickets и выгружается в данные игрока при его выходе. Плагин сохраняет это поведение и не создаёт копии жемчуга. Изменение ванильных tickets требует настройки сервера; плагин не меняет её автоматически.

Граница API: после физического столкновения жемчуга его расходование необратимо. Выход после уже завершённого снятия плиты не может восстановить израсходованный жемчуг. Плагин отменяет загрузку, пока выпуск ещё не подтверждён, но не подменяет физику телепортацией. Прямой `/setblock`, редакторы мира и другие плагины могут обойти Bukkit-события защиты; исправление таких изменений требует проверки самого сервера.

Повреждённый `.dat` намеренно блокирует включение плагина с явной ошибкой; исходный файл не перезаписывается. Перед восстановлением файла держать мир камеры выгруженным, чтобы отключённая защита не отпустила плиту.
